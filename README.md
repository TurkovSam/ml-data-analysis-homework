## 1. Постановка задачи и выбор данных
* **Бизнес-постановка задачи:** Создание модуля автоматического анализа веб-ссылок (URL) для корпоративной системы обнаружения угроз (IDS/SIEM), который позволит в реальном времени блокировать фишинговые и вредоносные сайты до того, как пользователь введет туда свои учетные данные.
* **ML-постановка задачи:** Задача бинарной классификации. 
  * **Объект:** Текстовая строка URL.
  * **Целевая переменная:** \(y &isin; \{0, 1\}\), где `0` — легитимный URL (`benign`), `1` — вредоносный/фишинговый URL (`malicious`).
* **Набор данных:** Используется открытый сбалансированный набор данных **"Web page Phishing Detection Dataset"**, автоматически загружаемый напрямую с Kaggle через библиотеку `kagglehub`. Датасет содержит **11 430 строк** и **89 признаков**, из которых для первичного анализа были извлечены сырой URL и целевой класс (столбец `status`).

---

## 2. Выбор и обоснование метрики
* **Предлагаемая метрика:** Комплексная метрика **F1-score**, а также жесткий контроль **Recall (полноты)** и **Precision (точности)** для целевого вредоносного класса.
* **Обоснование:** 
  1. Для данной задачи базовая метрика Accuracy (доля правильных ответов) неэффективна, так как она не учитывает внутреннюю структуру ошибок классификации.
  2. В сфере информационной безопасности (ИБ) критически важно минимизировать пропуски атак (ошибки *False Negatives*). Нам необходима максимальная полнота (**Recall**), чтобы заблокировать опасный сайт до момента ввода данных пользователем.
  3. С другой стороны, модель не должна достигать высокого Recall за счет слепой блокировки всех ссылок подряд. Слишком частые ложные срабатывания (*False Positives*) закроют сотрудникам доступ к легитимным ресурсам и нарушат бизнес-процессы компании.
  4. Метрика **F1-score** (среднее гармоническое Precision и Recall) обеспечивает необходимый баланс, удерживая систему от перекоса в сторону одного типа ошибок и гарантируя надежность ИБ-модуля.

## 3. Ключевые результаты разведочного анализа (EDA)
По результатам работы скрипта были рассчитаны базовые статистики и построены визуализации на базе `matplotlib` и `seaborn`:
* **Баланс классов:** Выборка является идеально сбалансированной (ровно по **50.0%** каждого класса — 5 715 строк на класс).
* **Анализ длины URL:** Выявлена сильная разделительная способность признака длины ссылки. Средняя длина безопасных URL составляет **47.38** символов, в то время как вредоносных — **74.85** символов (с экстремальными выбросами фишинга до **1641** символа). Злоумышленники существенно удлиняют ссылки для маскировки поддоменов.
* **Анализ HTTPS:** Визуализация доказала, что на защищенном протоколе HTTPS (`is_https = 1`) подавляющее большинство сайтов являются легитимными (`benign`). Напротив, на незащищенном HTTP лавинообразно доминируют вредоносные ресурсы (`malicious`), так как создатели фишинга экономят ресурсы на SSL/TLS сертификации сайтов-однодневок.
